# Наследование

## Подтип должен сохранять обещание
Наследование позволяет использовать поведение базового класса и уточнять его в подклассе. Однако сходство нескольких строк кода само по себе не является достаточной причиной для иерархии. Важен смысл: можно ли передать подкласс туда, где ожидается базовый тип, сохранив обещанный контракт? Если подкласс неожиданно запрещает обычную операцию, вызывающий код теряет предсказуемость.

Базовый класс может задавать общий интерфейс, а подклассы — разные реализации. При этом публичные параметры и смысл результата должны оставаться согласованными. Более строгие скрытые условия в подклассе способны нарушить заменяемость, даже если синтаксис метода совпадает. Проверяйте не только наличие имени метода, но и поведение на одинаковых сценариях.

Если требуется просто использовать отдельную возможность другого объекта, композиция часто выражает это точнее. Объект отчёта может содержать форматтер, не являясь разновидностью форматтера. Наследование и хранение зависимости решают разные задачи. Выбирайте отношение по модели предметной области, а не по желанию избежать любого повторения.

## Переопределение и super
Подкласс может переопределить метод. Вызов через экземпляр использует подходящую реализацию по правилам поиска. Если нужно дополнить базовое поведение, `super` продолжает поиск по порядку разрешения методов, а не просто создаёт отдельный «родительский объект». Это различие становится особенно важным при множественном наследовании.

В простой цепочке метод подкласса может получить базовый результат и добавить собственную часть. Порядок действий определяет результат: сначала базовая подпись, затем дополнение либо наоборот. Не забывайте вернуть вычисленное значение. Вызов базового метода без возврата результата способен превратить корректный текст в `None` для внешнего пользователя.

Инициализация также требует согласованности. Если подкласс определил собственный конструктор и базовому классу нужна настройка, её следует выполнить предусмотренным способом. Не предполагайте, что все родительские действия произошли независимо от переопределения. Проверьте, какие атрибуты должны существовать после создания экземпляра.

## Порядок поиска и глубина иерархии
Порядок разрешения методов доступен для анализа, но не должен становиться загадкой, которую приходится решать при каждом вызове. Глубокая иерархия с многочисленными частичными переопределениями делает последствия изменения базового метода трудными для оценки. Небольшие связные классы и явные зависимости часто проще сопровождать.

Общее изменяемое состояние базового класса остаётся общим по своим правилам и для подклассов, если не создано отдельное состояние экземпляров. Наследование не означает автоматического глубокого копирования атрибутов. Это особенно опасно для списков, кешей и накопителей, которые по смыслу должны принадлежать одному объекту.

Проверьте базовый и производный класс одним набором контрактных сценариев, затем добавьте специфические проверки расширения. Так видно, где сохранено общее обещание и где поведение осознанно отличается. Если тест требует постоянных проверок конкретного подкласса в вызывающем коде, возможно, исходная иерархия не выражает нужную границу.
