# Списки

## Изменяющий метод и новое значение
Список поддерживает изменение содержимого. `append`, `extend` и `sort` работают с существующим объектом и обычно возвращают `None`. Поэтому присваивание результата `append` имени списка теряет ссылку на сам список и сохраняет `None`. Сначала определите, нужен ли эффект над текущим контейнером или новое значение для дальнейшего выражения.

`sorted` возвращает новый отсортированный список, а `list.sort` меняет текущий. Выбор влияет на другие имена, которые указывают на тот же объект. Если исходный порядок ещё нужен для отчёта или сравнения, используйте новую коллекцию либо явно скопируйте исходную. Не считайте сортировку только способом отображения: она может изменить состояние программы.

`append` добавляет один объект, даже если этим объектом является список. `extend` перебирает источник и добавляет его элементы. После добавления списка через `append` появляется вложенность, а после `extend` обычно увеличивается плоская последовательность. Проверьте форму результата, прежде чем обращаться к индексам или считать длину.

## Поверхностная копия и вложенность
Присваивание `copied = original` создаёт второе имя того же списка. Метод `copy` или полный срез создаёт новый внешний список. Для плоских чисел этого достаточно, чтобы добавлять элементы независимо. Для списка списков внутренние контейнеры по-прежнему могут быть общими: поверхностная копия не дублирует всё дерево объектов.

Особенно внимательно относитесь к повторению списков через умножение. Несколько позиций могут ссылаться на один вложенный список. Изменение одной строки такой «матрицы» станет видно в других строках. Создавайте каждую вложенную строку независимо, если по смыслу они должны иметь отдельное состояние. Красивый первоначальный вывод не показывает различие ссылок.

Для проверки независимости выполните именно то изменение, от которого требуется защита. Если нужно независимо добавлять внешние элементы, проверяйте внешний `append`. Если нужно независимо менять вложенную строку, измените вложенный элемент. Одна проверка длины не доказывает глубокую независимость всех объектов.

## Индексы, удаление и устойчивый обход
Прямой индекс должен существовать. Отрицательные индексы удобны для последних элементов, но пустой список всё равно требует предусмотренной обработки. Срез выбирает диапазон с исключённой правой границей. Перед сложной комбинацией срезов подпишите, какие позиции должны попасть в результат, и проверьте небольшой пример вручную.

При удалении элементов во время обхода оставшиеся позиции сдвигаются. Следующая итерация способна перескочить через элемент, который оказался на уже пройденной позиции. Для отбора обычно проще построить новый список подходящих элементов. Если требуется изменение на месте, алгоритм должен явно учитывать сдвиг и порядок удаления.

Проверяйте пустой список, один элемент, повторы и несколько одинаковых элементов подряд. Последний случай особенно полезен для ошибок удаления. Для операции копирования проверьте также исходный список после изменения копии. Условие «вернуть правильный результат» может включать требование сохранить исходные данные, даже если итоговые числа совпадают.
