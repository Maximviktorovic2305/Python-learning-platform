# SQLite

## Соединение владеет контекстом работы
SQLite является встраиваемой СУБД: приложение работает с библиотекой, а не обязано подключаться к отдельному сетевому серверу. Файловая база сохраняет данные в выбранном файле; `:memory:` создаёт учебное хранилище в памяти для соответствующего соединения. Закрытие такого соединения завершает срок жизни его данных.

Соединение нужно освобождать явно в понятном владельце ресурса. Контекст транзакции и закрытие соединения являются различными вопросами: удобный `with connection` помогает commit или rollback по своим правилам, но не следует считать его универсальным обещанием закрыть объект. Проверьте контракт используемого API и примените `finally` или предназначенный менеджер закрытия.

Не открывайте новое соединение в каждой строке одного связанного сценария. Тогда операции могут попасть в разные транзакции, а `:memory:` — в разные базы. Создайте границу работы, выполните нужные команды и корректно завершите ресурс. Для серверного приложения дополнительно учитывайте модель конкурентного доступа и настройки драйвера.

## Значение с кавычкой остаётся значением
Placeholder `?` обозначает место параметра, который передаётся отдельной последовательностью. Один параметр обычно передают кортежем из одного элемента с запятой. Простая строка не является эквивалентом такого кортежа и может интерпретироваться драйвером как последовательность символов. Форма аргумента является частью контракта выполнения.

Апостроф внутри имени не должен превращаться в часть синтаксиса команды. При раздельной передаче SQL и параметров драйвер сохраняет значение как данные. Не конкатенируйте ввод с SQL и не пишите собственное «исправление кавычек» вместо параметризации. Самодельное экранирование часто не покрывает все случаи и смешивает обязанности.

Параметрами нельзя подставлять произвольную структуру SQL так же, как значение поля. Для разрешённых способов сортировки выберите готовое имя столбца из контролируемого набора, а значения фильтра передайте отдельно. Так внешний ввод не получает возможность менять назначение запроса под видом обычного параметра.

## Результат запроса и пустой поиск
`fetchone` получает одну строку результата или `None`, если строки отсутствуют. Не обращайтесь к первому элементу до обработки отсутствия, если запрос действительно может ничего не найти. Агрегат `COUNT(*)` имеет иной контракт: он возвращает строку с числом, включая ноль, поэтому его не следует путать с поиском отдельной записи.

Результат обычно представлен последовательностью значений столбцов в заданном порядке. Явно перечисляйте нужные столбцы вместо зависимости от случайной структуры `SELECT *`, особенно для публичного ответа. Служебные поля и парольные данные не должны попадать наружу просто потому, что они существуют в таблице.

Проверьте вставку значения с апострофом, обычного Unicode-текста и допустимого пустого значения. Затем проверьте отсутствие записи и конфликт уникальности. Отдельный тест на rollback должен различать уже зафиксированные данные и текущую незафиксированную работу. Это демонстрирует реальные свойства соединения, которые нельзя подтвердить одним успешным `SELECT`.
