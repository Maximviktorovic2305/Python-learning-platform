# Циклы

## Что меняется на каждой итерации
У цикла есть источник значений, тело и условие продолжения по правилам выбранной конструкции. `for` получает очередной элемент из итерируемого объекта; он не обязательно перебирает номера. Если нужен именно элемент, прямой перебор обычно понятнее ручного получения индекса. `while` повторяет тело, пока условие истинно, и требует особенно внимательно следить за изменением состояния.

До цикла определите начальное состояние накопителя. Для суммы это обычно ноль, для списка результатов — пустой список. Во время каждой итерации выполняется одна понятная операция над состоянием. После цикла накопитель выражает результат для всех обработанных элементов. Если создавать его заново внутри тела, предыдущие итерации будут забыты.

Полезно сформулировать инвариант: после обработки первых нескольких элементов сумма содержит именно их вклад. Такое предложение позволяет проверить порядок операций. Если элемент-маркер не должен входить в сумму, его проверяют раньше прибавления. Неверный порядок легко пропустить, когда код рассматривается только как список отдельных строк.

## Пропуск и завершение различаются
`continue` завершает текущую итерацию и переходит к следующему значению, а `break` завершает весь ближайший цикл. Поэтому отрицательное число может быть либо элементом, который требуется пропустить, либо маркером конца данных. Это разные условия задачи, хотя обе программы содержат проверку отрицательности.

`else` у цикла относится к завершению без `break`, а не к последнему условию внутри тела. Такой приём бывает удобен для поиска: если элемент найден, выполняется `break`; если цикл исчерпал значения, выполняется `else`. Прежде чем использовать конструкцию, объясните её смысл словами. Если команда команды проекта не знакома с этим правилом, явный результат поиска иногда читается проще.

Вложенный `break` завершает только ближайший цикл. Для выхода из более сложного сценария можно вернуть результат из функции или явно передать состояние внешнему уровню. Не рассчитывайте, что один оператор автоматически прекращает все уровни вложенности. Проследите, какая конструкция непосредственно содержит его.

## Пустой источник и изменение коллекции
Пустая коллекция означает ноль итераций. Итоговый результат должен следовать из начального состояния: сумма остаётся нулём, отфильтрованный список пустым. Если переменная создаётся только внутри тела, после пустого цикла она может отсутствовать. Отдельная проверка пустого источника быстро выявляет такие предположения.

Не меняйте длину списка во время прямого обхода без понимания правил итератора: элементы могут быть пропущены или обработаны неожиданно. Часто лучше строить новый список, обходить копию или использовать подходящее выражение отбора. Изменение содержимого и изменение структуры коллекции являются разными действиями с разными последствиями.

Для проверки остановки используйте данные до маркера, сам маркер и несколько значений после него. Для `while` убедитесь, что каждый возможный путь тела приближает условие к завершению либо имеет осмысленный выход. Особенно опасна ветвь `continue`, которая пропускает изменение счётчика и превращает обычный цикл в бесконечный.
