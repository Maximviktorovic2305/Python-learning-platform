# Переменные

## Имя связано со значением
Присваивание сначала вычисляет правую часть, затем связывает результат с именем слева. В записи `count = count + 1` прежний `count` нужен для вычисления выражения; после этого имя получает новое число. Это не математическое равенство, требующее одновременного выполнения обеих сторон. Поэтому такое присваивание имеет смысл при уже существующем значении имени.

Если имя ещё не определено, чтение вызывает ошибку. Редактор может подсветить проблему заранее, но фактический порядок выполнения остаётся решающим. В большом файле полезно находить не только объявление имени, но и все места его изменения. Имя должно отражать роль текущего значения, иначе после нескольких присваиваний становится трудно понять, что именно оно обозначает.

Python не требует заранее объявить числовой тип переменной. Имя можно позднее связать с другим объектом, но постоянная смена смыслов и типов усложняет чтение. Удобнее использовать отдельные имена для исходного текста, преобразованного числа и вычисленного результата, когда эти значения нужны одновременно.

## Сохранённое значение не является формулой
Когда новое имя получает результат выражения, оно хранит эту привязку, а не правило постоянного пересчёта. Если `total` вычислен из цены и количества, последующее изменение количества не обновит `total` автоматически. Для нового результата нужно снова вычислить выражение. Это важное различие между выполнением программы и электронными таблицами с зависимыми формулами.

Так же работает сохранение старого числа перед изменением. Два имени первоначально могут обозначать одно числовое значение. Переприсваивание одного имени не заставляет второе искать новое значение через первое. Позже, при изучении изменяемых списков, появится другой случай: разные имена будут наблюдать изменения одного общего контейнера. Сейчас важно не смешивать перепривязку имени и изменение самого объекта.

Для ручной трассировки составьте таблицу с колонками «строка», «имя», «значение». Записывайте только изменения после завершения команды. Это помогает обнаружить использование старой величины, случайное перезаписывание исходных данных и пропущенное повторное вычисление результата.

## Имена и границы ответственности
Хорошее имя отвечает на вопрос, что означает значение: `price`, `quantity`, `previous`, `result`. Однобуквенные имена допустимы в небольшом очевидном контексте, но теряют смысл в длинном сценарии. Не называйте переменные `list`, `str` или `sum`, когда собираетесь использовать одноимённые встроенные инструменты: новая привязка скроет привычное значение имени.

Избегайте нескольких несвязанных действий в одной строке только ради краткости. Ясная последовательность присваиваний позволяет проверить промежуточный результат и объяснить ошибку. Комментарий должен описывать намерение, а не повторять синтаксис вроде «прибавляем единицу» рядом с очевидным сложением.

После написания решения проверьте минимальное, обычное и неудобное исходное значение. Например, ноль и отрицательное число обнаруживают предположение, что исходная величина всегда положительна. Если по условию ограничений нет, программа не должна молча добавлять их сама. Сохранение исходного и нового значений под разными именами делает такую проверку особенно наглядной.
