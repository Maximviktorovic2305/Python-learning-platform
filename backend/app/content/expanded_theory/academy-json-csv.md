# JSON и CSV

## Формат является набором правил
JSON описывает структурированные значения: объекты, массивы, строки, числа, логические значения и отсутствие значения. CSV представляет табличные поля и записи, но конкретный диалект задаёт разделитель, кавычки и окончания строк. Похожее расширение файла не проверяет соответствие содержимого формату. Разбор должен выполняться подходящей библиотекой и сопровождаться обработкой ошибки.

Строка Python с JSON-текстом и уже разобранный словарь являются разными представлениями. `loads` разбирает текст, `dumps` сериализует значение в текст; варианты `load` и `dump` работают с файловым объектом. Не сериализуйте уже сериализованный текст повторно без необходимости: получите строку с экранированным JSON внутри вместо исходной структуры.

В JSON ключи объектов строковые. Некоторые Python-структуры не имеют прямого эквивалента или преобразуются с потерей деталей, например кортеж становится массивом. Перед обменом данными определите допустимую схему. Возможность сериализации не означает сохранение всех свойств исходного Python-объекта.

## Синтаксический разбор не проверяет предметный контракт
Успешный `json.loads` подтверждает корректность JSON-синтаксиса, но не наличие нужного поля, правильный тип или допустимый диапазон. Клиент может прислать массив вместо объекта, `null` вместо строки и лишние поля. После парсера нужна проверка структуры и смысловых ограничений. Не обращайтесь к глубоко вложенным полям, пока форма внешних данных не установлена.

CSV обычно возвращает текстовые поля. Числа и даты преобразуйте явно и сообщайте о неправильном формате. Пустое поле может обозначать отсутствие значения либо пустую строку — это решение схемы данных. Автоматическое превращение любого пустого поля в ноль меняет смысл документа и способно скрыть пропуск обязательного значения.

Для больших документов учитывайте объём памяти и ограничения размера. Удобное полное чтение подходит маленькому учебному примеру, но не является единственным способом обработки. Сначала установите допустимый размер, затем выбирайте потоковый подход, если он нужен. Корректный формат не гарантирует разумную стоимость обработки.

## Разделители внутри полей
CSV допускает запятую внутри поля, заключённого в кавычки, а кавычки внутри такого поля имеют собственное экранирование. Обычный `split(',')` этих правил не понимает и разбивает данные неверно. Так же обычный `join` не может безопасно сформировать произвольную CSV-строку. Используйте `csv.reader` и `csv.writer` с согласованным диалектом.

`StringIO` позволяет показать этот механизм без обращения к настоящему файлу: writer пишет в текстовый буфер, reader читает из него. Это полезно для небольших тестов и преобразований. При работе с файловым CSV учитывайте рекомендацию библиотеки по параметру `newline`, чтобы не добавлять лишние окончания строк на некоторых платформах.

Проверьте поле с запятой, кавычкой, пустым значением и не-ASCII текстом. Затем прочитайте сформированный документ обратно и сравните восстановленные значения. Такой круговой тест полезен для сохранности формата, но не заменяет независимую проверку ожидаемой внешней схемы: одинаково неверные запись и чтение могут скрыть общую ошибку соглашения.
