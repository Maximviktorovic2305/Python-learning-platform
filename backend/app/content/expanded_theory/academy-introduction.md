# Введение

## От намерения к точной последовательности
Человек легко понимает просьбу «посчитай покупку», потому что достраивает недостающие детали из опыта. Компьютеру нужны определённые данные и действия. Сначала назовите исходные величины, затем действие над ними и форму результата. Стоимость может быть числом, а строка «Стоимость: 120» — способом показать это число человеку. Вычисление и оформление результата связаны, но выполняют разные задачи.

Программа исполняется последовательно: следующая команда видит последствия уже выполненных команд. Если сначала вывести значение, а потом изменить его, напечатанный результат не изменится задним числом. Вывод — событие, которое уже произошло. Такой взгляд помогает читать даже незнакомый код: двигайтесь сверху вниз и записывайте значения после каждого действия. Не пытайтесь сразу угадать назначение всей программы по её последней строке.

Начинайте с одной проверяемой цели. Например, показать подпись и имя, затем показать только имя. У каждой строки будет понятное назначение. Когда результат отличается от ожидаемого, можно проверить конкретный шаг вместо случайного переписывания всей программы.

## Исходный код, литерал и значение
Исходный файл содержит запись команд. Кавычки в этой записи помогают интерпретатору распознать строковый литерал; обычно сами кавычки в вывод не попадают. Имя без кавычек обозначает обращение к ранее связанному значению. Поэтому текст `city` внутри кавычек и имя `city` вне кавычек имеют разный смысл, даже когда выглядят почти одинаково.

Аргументы `print` вычисляются до печати. Переданное число выводится как его текстовое представление, строка — как содержащиеся в ней символы. Несколько аргументов по умолчанию разделяются пробелом, а завершение вызова добавляет перевод строки. Два отдельных вызова дают две строки; один вызов с двумя аргументами обычно даёт одну. Это часть наблюдаемого поведения программы, а не оформление редактора.

Не вводите в поле исходного кода приглашения терминала вроде `>>>`, если это не часть самого примера. Приглашение показывает, что интерактивный интерпретатор готов принять команду. Файл программы должен содержать команды, которые он принимает, а не текст интерфейса вокруг них.

## Три способа заметить неправильный результат
Синтаксическую ошибку интерпретатор обнаружит при разборе файла. Ошибка выполнения появится на конкретном действии после начала работы. Логическая ошибка может дать полностью успешное завершение с неправильным ответом. Отсутствие красного сообщения поэтому не является доказательством правильности: сравнивайте смысл и точный результат с задачей.

Полезный порядок разбора таков: убедиться, что выполнен нужный файл; прочитать последнее сообщение ошибки; найти указанную строку; выяснить значения, с которыми она работает. Меняйте одну причину за раз. Если одновременно исправлять кавычки, имена и порядок действий, трудно понять, какое изменение помогло.

После успешного запуска измените исходное имя или число. Правильная программа использует данные, а не заранее напечатанный ответ для одного примера. Объясните вслух, какие строки вывода поменяются и почему. Такая небольшая проверка превращает запуск из механического нажатия кнопки в проверку понимания исполнения.
