# SQLAlchemy Core

## Объекты выражений описывают SQL
SQLAlchemy Core предоставляет способ строить SQL-выражения средствами Python. Таблица, столбец и `select` являются объектами описания, а не уже загруженными данными. Запрос выполняется, когда выражение передано подходящему соединению. Это различие позволяет отдельно рассуждать о структуре запроса и о конкретном обращении к БД.

`Engine` управляет инфраструктурой подключения и пулом, а `Connection` представляет конкретный контекст выполнения. Не создавайте новый engine для каждого простого запроса в серверном приложении. Такой подход размножает пулы и затрудняет управление ресурсами. Обычно общий инфраструктурный владелец создаёт engine и освобождает его при завершении приложения.

`MetaData` и `Table` описывают схему в памяти Python. Метод создания таблиц полезен для изолированного учебного примера, но не является универсальной стратегией миграции рабочей базы. Для развития схемы нужны версионируемые миграции, совместимость релизов и проверка на тестовых данных. Не удаляйте рабочую схему ради повторения упражнения.

## Транзакционный контекст
`engine.begin()` предоставляет соединение в транзакционном контексте: обычное завершение фиксирует работу, исключение приводит к предусмотренному откату. Если исключение перехватить внутри блока и скрыть, внешний контекст может не увидеть отказ так, как вы ожидали. Граница обработки ошибки должна соответствовать границе согласованного сценария.

Используйте переданное соединение для всех операций одной транзакции. Создание отдельного соединения посредине не делает его автоматически частью уже открытой работы. Для связанных записей нужно явное единое владение контекстом. Не распределяйте commit по случайным вспомогательным функциям, если приложение должно управлять сценарием целиком.

Параметры выражений сохраняют различие между данными и SQL. Тем не менее типизированный конструктор запроса не заменяет авторизацию: фильтр по владельцу и ограничение объёма должны быть предусмотрены самим сценарием. Удобный API не доказывает, что запрос разрешён конкретному пользователю.

## Row, scalar и агрегаты
Результат выполнения содержит строки и предоставляет способы извлечения данных. `scalar` выбирает одно значение, `scalars` — последовательность значений первого столбца. Выбирайте форму по ожидаемому контракту, чтобы вызывающий код не получал неожиданную обёртку `Row` вместо числа или строки. Несколько столбцов требуют более явной обработки.

Агрегаты выполняют вычисление в БД. `COUNT` и `SUM` имеют разные результаты на пустом наборе: сумма может отсутствовать по SQL-правилам, если это не обработано явно. Не подставляйте ноль случайно, пока не определён смысл отсутствия. Для отчёта такое правило часто допустимо, но должно быть выражено в запросе или на границе результата.

Проверьте пустой набор, несколько записей, отрицательные значения и отказ ограничения. Если порядок важен, добавьте `order_by`; способ выполнения Core не создаёт гарантированный порядок сам. Тест с настоящим SQLite подтверждает учебный контракт этой СУБД, но не все особенности блокировок и конкурентности PostgreSQL.
