# Множества

## Уникальность меняет представление
Множество хранит различные хешируемые значения. Повторное добавление уже существующего элемента не создаёт вторую позицию. Это удобно для вопроса «встречалось ли значение», но непригодно для сохранения частот. Если слово встретилось пять раз, после преобразования в множество остаётся только факт его наличия. Исходное количество появлений восстановить из этого представления нельзя.

Порядок множества не является порядком исходного списка. Не используйте произвольный порядок обхода для отчёта, в котором требуется воспроизводимый результат. Примените `sorted` при выводе, если договорённость требует алфавитного порядка. Если нужен порядок первого появления, можно использовать отдельный список вместе с набором уже встреченных элементов или подходящий словарный приём.

Для пустого множества используется `set()`. Пустые фигурные скобки создают словарь. По мере чтения кода проверяйте не только внешнюю форму литерала, но и операции, которые затем выполняются. Ошибка типа может возникнуть далеко от места, где неверно выбран пустой контейнер.

## Операции выражают отношение двух наборов
Объединение содержит всё, что есть хотя бы в одном наборе. Пересечение выбирает общие элементы. Разность выбирает элементы левого набора, которых нет в правом. Симметрическая разность оставляет элементы, присутствующие только с одной стороны. Эти операции удобно переводятся в конкретные вопросы: общие навыки, недостающие требования или различия конфигураций.

Направление разности существенно. `required - known` означает недостающие требования, а `known - required` — дополнительные знания сверх требований. Поменять операнды местами значит задать другой вопрос, а не просто изменить оформление записи. Подставьте по одному элементу, который есть только слева, только справа и в обоих наборах, чтобы проверить понимание.

Проверка подмножества отвечает, включены ли все элементы одного набора в другой. Она не сравнивает длины напрямую: два набора одинаковой длины могут иметь совершенно разный состав. Если нужно проверить выполнение всех требований, важен состав и включение, а не количество перечисленных пунктов.

## Хешируемость и границы алгоритма
Элемент множества должен иметь подходящее устойчивое представление для хеширования. Обычный список нельзя добавить как элемент, поскольку его содержимое изменяемо. Если данные логически являются неизменяемой парой, иногда подходит кортеж хешируемых значений. Не превращайте произвольную вложенную структуру в строку только ради обхода ограничения: такое представление может потерять нужный смысл сравнения.

В типичных условиях проверка принадлежности множеству эффективна, но создание набора требует отдельной памяти. Для большого источника оцените, действительно ли нужно хранить все уникальные значения одновременно. Выбор структуры должен следовать требуемым операциям и ограничениям, а не общему правилу «множество всегда лучше списка».

Проверьте пустые наборы, полное совпадение, отсутствие пересечения и повторяющиеся исходные значения. Для вывода отсутствующих требований определите, что означает пустая разность: пустую строку, специальную подпись или иной результат. Это внешний контракт программы, который нельзя оставлять случайному отображению `set()`.
