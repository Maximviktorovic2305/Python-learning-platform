# Области видимости

## Как Python выбирает привязку
Имя ищется в доступных областях видимости по правилам языка, а не по ближайшей строке текста. Для обычной функции важны локальная область, окружающие функции, модуль и встроенные имена. Если одинаковое имя встречается на разных уровнях, это могут быть независимые привязки. Вызов другой функции сам по себе не передаёт ей все локальные имена вызывающего кода.

Присваивание внутри функции обычно делает имя локальным для этого тела. Поэтому чтение имени перед его локальным присваиванием может вызвать `UnboundLocalError`, даже если в модуле есть одноимённая переменная. Интерпретатор не переключается на глобальное значение только потому, что локальное присваивание ещё не произошло. Сначала найдите все присваивания в теле, затем рассуждайте о чтении.

Не используйте `global` как автоматическое средство исправления любой ошибки имени. Он меняет смысл зависимости: функция начинает работать с состоянием модуля, которое могут менять другие вызовы. Часто правильнее принять значение параметром и вернуть новое значение явно. Тогда вызов можно понять и протестировать без скрытой предварительной настройки.

## Изменение объекта и перепривязка имени
Если параметр содержит список, вызов его `append` изменяет общий объект. Для этого не нужен `global`, потому что имя остаётся связано с тем же списком. Если вместо этого присвоить параметру новый список, изменится локальная привязка; внешнее имя продолжит обозначать прежний объект. Эти действия похожи словами «изменить список», но различаются наблюдаемым поведением.

Рассуждайте отдельно об именах и объектах. Несколько имён способны указывать на один объект. Новое присваивание переключает конкретное имя, а изменение содержимого видно через все оставшиеся ссылки на объект. Такая модель объясняет и передачу аргументов, и поведение контейнеров без предположения, что Python копирует всё при каждом вызове.

Побочный эффект становится опасным, если вызывающий код его не ожидает. Не храните текущий запрос, пользователя или временный результат в глобальной переменной ради передачи между функциями. В последовательном примере это может работать, но при нескольких вызовах и конкурентной обработке результаты смешаются. Явные параметры остаются самым понятным исходным решением.

## Замыкание и независимое сохранённое состояние
Вложенная функция может продолжать использовать привязки окружающей функции после её завершения. Это замыкание. Оно удобно для сохранённой настройки или небольшого счётчика. При этом сохраняется доступ к привязке, а не замороженный снимок значения в момент записи каждой строки. Изменения во внешней области могут быть видны последующим вызовам замыкания.

`nonlocal` явно выбирает уже существующее имя окружающей функции для перепривязки. Он не создаёт произвольное внешнее имя и не означает глобальную переменную модуля. Если фабрику счётчика вызвать дважды, каждый вызов создаст собственную область и собственный счётчик. Если же два имени получают одну возвращённую функцию, они используют общее сохранённое состояние.

Проверяйте замыкание несколькими последовательными вызовами, затем создайте второе независимое замыкание. Так видно, какое состояние должно сохраняться, а какое оставаться отдельным. Для чтения вложенного кода подпишите, в какой функции определено каждое имя, и отметьте места `nonlocal`. Это делает даже несколько уровней вложенности проверяемыми по шагам.
