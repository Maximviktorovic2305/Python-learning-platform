# Стандартная библиотека

## Выбираем инструмент по структуре задачи
Стандартная библиотека устанавливается вместе с Python и покрывает множество повседневных операций: коллекции, пути, даты, форматы данных и тестирование. Это не означает, что все модули автоматически импортированы или одинаково доступны в любой среде. Возможности, связанные с операционной системой, могут быть ограничены в браузерном runtime.

Начинайте с формы данных и требуемого действия. Для частот подходит `Counter`, для пути — `pathlib`, для JSON — специализированный парсер. Название модуля не заменяет чтение контракта. Даже знакомая операция может иметь важное поведение на пустом входе или сохранять порядок иначе, чем ожидается по обычному примеру.

Готовая функция часто выражает намерение точнее ручной реализации. Однако не объединяйте несколько непонятных вызовов в длинную строку только ради краткости. Сохранённые промежуточные значения помогают увидеть, что именно вернул каждый шаг и где возникло несоответствие типу или смыслу.

## Частоты и пустые данные
`Counter` хранит частоты элементов и даёт нулевую частоту при чтении отсутствующего элемента. Это удобно для подсчёта слов, событий и категорий. Но сам факт создания счётчика не выбирает способ отчёта: максимальную частоту, самые частые элементы, алфавитный список или сохранение порядка определяет задача.

Если нужно найти максимум частот, отдельно предусмотрите пустой источник. У `max` есть параметр `default`, который задаёт результат при отсутствии элементов. Это отличается от добавления фиктивного значения в сами данные. Пустой отчёт может корректно означать нулевую частоту, но такое правило должно быть выбрано явно.

Проверяйте отсутствующий ключ и существующий ключ с нулевой частотой как разные случаи, если выполняли дополнительные изменения счётчика. Словареподобный интерфейс не делает все методы `Counter` полностью тождественными обычному словарю. Читайте описание конкретной операции, особенно при арифметике нескольких счётчиков и удалении нулевых значений.

## Случайность и детерминированные проверки
Случайный результат затрудняет повторение ошибки, если программа не сохраняет условия генерации. Отдельный экземпляр `random.Random` с заданным seed позволяет управлять последовательностью, не изменяя общий генератор всего процесса. Это полезно для учебных примеров и воспроизводимых наборов данных, но не является подходящим инструментом генерации секретов.

Для паролей, токенов и других чувствительных случайных значений используют предназначенные для этого криптографические средства. Не подменяйте безопасность фиксированным seed ради удобства проверки. Тест может проверять формат и ограничения секрета, не требуя заранее известного значения самого секрета.

Применяйте тот же принцип к времени и внешним данным: контролируйте источник зависимости в тесте, а не заставляйте тест надеяться на удачное совпадение. Стандартная библиотека предоставляет много полезных механизмов, но ясная граница зависимости остаётся частью архитектуры вашей программы. Это особенно заметно, когда один и тот же код запускается локально, в контейнере и в браузере.
