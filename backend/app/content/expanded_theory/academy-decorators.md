# Декораторы

## Обёртка получает и возвращает функцию
Декоратор получает исходный вызываемый объект и возвращает объект, который будет связан с именем вместо него. Синтаксис с `@` выражает это преобразование рядом с определением. При обычном декораторе функции изменение привязки происходит при выполнении определения, а тело обёртки работает при последующем вызове.

Возвращённая обёртка должна сохранить нужный контракт аргументов и результата. Если исходная функция возвращает число, забытый `return` в wrapper превращает внешний результат в `None`. Если wrapper не принимает нужные аргументы, прежний правильный вызов начнёт завершаться ошибкой. Декоратор может дополнять поведение, но ответственность за совместимость остаётся у автора.

Различайте действие при создании обёртки и действие при каждом вызове. Настройку, которая должна сохраняться, можно захватить замыканием. Логирование отдельного вызова, измерение или преобразование результата выполняются внутри wrapper. Ошибка в выборе стадии приводит к тому, что сообщение появляется только при импорте вместо каждого использования функции.

## Метаданные и порядок композиции
Без дополнительной настройки wrapper имеет собственное имя и документацию. `functools.wraps` переносит важные метаданные исходной функции и сохраняет связь с ней для инструментов. Он не выполняет вычисление вместо wrapper, не передаёт аргументы автоматически и не исправляет забытый возврат. Это отдельная задача совместимости описания функции.

Несколько декораторов применяются в определённом порядке вложенности. Внешняя обёртка первой получает вызов, а результат проходит внутренние и внешние преобразования по их композиции. Для добавления строки и удвоения числа перестановка может менять смысл. Перепишите запись в виде обычных вложенных вызовов, если порядок трудно увидеть по нескольким строкам `@`.

Не делайте набор обёрток непрозрачным для ошибки. Понятные имена, сохранённые метаданные и небольшой отдельный тест помогают понять, какой слой изменил результат или выбросил исключение. Общая магическая обёртка для всех задач обычно сложнее нескольких узких декораторов с явным назначением.

## Граница побочных действий
Декоратор логирования не должен бездумно печатать все аргументы: среди них могут быть пароли, токены и пользовательский текст. Декоратор повторов не должен автоматически повторять необратимое действие без политики идемпотентности. Удобная универсальная форма не отменяет предметный смысл конкретного вызова и стоимость ошибки.

Для асинхронной функции требуется обёртка, которая корректно работает с ожидаемым результатом, а не просто возвращает объект корутины как обычное вычисленное значение. Сохранение метаданных и управление исполнением остаются разными задачами. Проверяйте и успешный путь, и исключение, чтобы обёртка не проглотила отказ или не оставила ресурс открытым.

Начните с декоратора, который делает ровно одно наблюдаемое преобразование результата. Проверьте обычное значение, ноль, аргументы по имени и имя функции после декорирования. Затем объясните, какая функция связана с публичным именем и когда вызывается исходная реализация. Такая трассировка полезнее запоминания шаблона wrapper без понимания замыкания.
