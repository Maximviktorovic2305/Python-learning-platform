# Атрибуты и методы

## Данные и вычислимые свойства
Атрибут может хранить состояние, а метод — выполнять действие или вычислять результат из текущего состояния. Если результат зависит от изменяемого поля, вычисление при обращении предотвращает устаревшую копию. Например, удвоение текущего числа должно читать текущее число, а не сохранённое однажды значение, если контракт не требует снимка.

Не каждый доступ с точкой является простым чтением из словаря атрибутов. Свойство `property` позволяет выполнить определённую логику при чтении или записи, сохранив удобный внешний синтаксис. Поэтому внешне одинаковое `item.value` может быть обычным полем или управляемым интерфейсом. Пользователь класса должен полагаться на его контракт, а не на предположение о внутреннем хранении.

Старайтесь не делать чтение свойства неожиданно дорогим или изменяющим состояние без ясного основания. Сетевой запрос, скрытый внутри простого обращения, затрудняет понимание времени и ошибок операции. Когда действие существенно, явный метод часто лучше выражает намерение и ожидаемый побочный эффект.

## Обычный, статический и классовый метод
Обычный метод получает экземпляр и работает с его состоянием. Классовый метод получает класс и может использоваться, например, для альтернативного способа создания объекта. Статический метод не получает автоматически ни экземпляр, ни класс. Эти варианты выбирают по нужной зависимости, а не ради стилистического разнообразия.

Если функция не использует состояние класса и логически не принадлежит его интерфейсу, обычная функция модуля иногда понятнее статического метода. Если альтернативный конструктор должен уважать подкласс, использование полученного класса вместо жёстко указанного имени базового класса сохраняет расширяемость. При этом не усложняйте интерфейс несколькими способами создания без реального сценария.

Вызов метода без круглых скобок получает вызываемый объект, а не результат вычисления. Это полезно при передаче функции как зависимости, но вызывает ошибку, если ожидалось число. Различайте «передать действие для будущего вызова» и «вызвать действие сейчас и передать его результат».

## Согласованность изменений
Если изменение атрибута влияет на другое состояние, определите единственное место, где поддерживается правило. Несколько независимых открытых полей могут позволить создать противоречивую комбинацию. Иногда достаточно вычислимого свойства, иногда нужен метод сценария, который проверяет весь набор перед изменением. Выбор зависит от смысла данных, а не от желания добавить больше декораторов.

Возвращаемый результат метода также должен быть определён: новое значение, сам объект для цепочки или `None` после изменения. Не смешивайте разные варианты случайно в соседних ветвях. Вызывающий код должен знать, можно ли использовать результат следующего выражения, независимо от того, что метод успешно изменил внутри.

Проверьте изменение основного поля и последующее чтение производного результата. Затем выполните два последовательных изменения и вызов на другом экземпляре. Такие проверки выявляют сохранённое устаревшее значение и случайное общее состояние. Ясно разделённые данные и действия делают поведение класса понятным даже без чтения каждой строки его реализации.
