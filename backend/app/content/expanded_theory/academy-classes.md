# Классы и объекты

## Создание экземпляра и инициализация
Вызов класса обычно создаёт экземпляр и выполняет его инициализацию. Метод `__init__` получает уже создаваемый объект как `self` и устанавливает допустимое начальное состояние. Он не должен возвращать произвольный результат вместо экземпляра. Параметры конструктора помогают сделать обязательные данные явными, чтобы объект не существовал в непонятном промежуточном состоянии.

Два вызова класса создают два экземпляра, даже если аргументы совпадают. Простое присваивание второго имени уже существующему объекту не вызывает конструктор. Это различие объясняет, почему изменение через псевдоним видно под первым именем. Число переменных в программе не равно числу объектов: несколько имён могут обозначать один экземпляр.

Проверяйте независимость практически: создайте два счётчика, измените один и прочитайте оба. Если изменились оба, выясните, создан ли общий контейнер на уровне класса или второе имя было связано с первым объектом. Не пытайтесь исправить такую проблему случайным переименованием переменных: причина находится в структуре ссылок.

## Метод связан с конкретным получателем
При обращении к методу через экземпляр Python связывает функцию с этим экземпляром. Поэтому `item.increment()` получает `item` как `self` без явного дополнительного аргумента. `self` является общепринятым именем параметра, а не отдельной магической глобальной переменной. Внутри метода оно обозначает объект текущего вызова.

Атрибуты читаются по правилам поиска, включающим экземпляр и класс. Если значение не найдено там, где вы ожидали, проверьте, действительно ли атрибут установлен в конструкторе и нет ли опечатки. Динамическая возможность создавать новые атрибуты не исправляет неправильное имя автоматически: программа может случайно добавить второе поле и оставить прежнее неизменным.

Выбирайте имена методов по действию или возвращаемому смыслу. Метод изменения и метод получения результата имеют разные ожидания. Не заставляйте вызывающий код угадывать, изменяет ли `calculate` объект или только возвращает число. Явный небольшой контракт упрощает и использование, и тесты.

## Представление и равенство
Текстовое представление объекта помогает диагностике, но не является самим объектом и не доказывает равенство состояний. Если класс предоставляет собственное сравнение, определите, какие поля выражают равенство по смыслу. Два аккаунта с одинаковым именем могут оставаться разными сущностями, тогда как две координаты с одинаковыми числами могут считаться равными значениями.

Не используйте адресоподобный фрагмент стандартного вывода объекта как устойчивый идентификатор данных. Он зависит от конкретного процесса. Для сохранения и обмена определите явные поля и формат сериализации. Класс с методами и открытыми ресурсами нельзя бездумно считать обычным JSON-объектом.

Небольшая последовательность проверок для класса включает корректное создание, недопустимое начальное значение, изменение состояния, повторный вызов и независимый второй экземпляр. Эти случаи раскрывают модель объекта лучше одного примера с красивым выводом. После проверки попробуйте объяснить, какие данные принадлежат экземпляру, какие классу и какие существуют только внутри вызова метода.
