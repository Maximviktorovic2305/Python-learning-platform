# Текстовые файлы

## Кодировка и границы строк
Текстовый файл хранит байты, которые интерпретируются по кодировке. Строка Python уже представляет декодированный текст. Переход между ними является отдельным действием, даже если удобный метод выполняет его автоматически. Для воспроизводимого формата задавайте кодировку явно и не считайте, что все компьютеры выбирают одну системную настройку.

Перевод строки тоже является данными. Пустая строка внутри документа может быть значимой, а завершающий перевод строки не обязательно означает дополнительную содержательную строку. Поэтому `split('\n')`, `splitlines` и прямой обход файла имеют различающиеся детали. Выберите операцию по определению требуемого количества строк, а не по случайному совпадению на одном примере.

Не удаляйте все пробельные символы из каждого фрагмента автоматически. Отступы важны для Python-кода, пробелы могут быть частью значения, а пустые строки — разделителями блоков. Для подсчёта непустых строк можно проверять `line.strip()`, сохраняя сам исходный текст без изменений. Проверка и преобразование — разные действия.

## Построчная обработка и накопление
Обход файлового объекта позволяет работать с последовательностью строк без обязательной загрузки всего файла в память. Счётчик увеличивается на каждом обработанном элементе, а накопитель создаётся до цикла. Если задача требует одновременно число всех и содержательных строк, заведите отдельные понятные показатели вместо случайного переиспользования одной переменной.

Метод `readline` возвращает очередную строку, а пустая строка как результат обозначает конец файла. Строка, содержащая только перевод строки, при этом не является концом. Такое различие помогает избежать преждевременной остановки на пустой строке документа. В `for` детали продвижения итератора обычно выражены проще и безопаснее.

Если данные разбиваются на поля, после чтения строки всё ещё остаётся вопрос формата. Разделение по произвольному пробельному набору подходит не для любого документа. Фиксированные разделители, кавычки или вложенные записи требуют соответствующего разбора. Чтение текста и понимание структуры текста являются последовательными, но разными этапами.

## Ошибки и проверка сохранности
Ошибка декодирования сообщает, что байты не соответствуют выбранным правилам. Режим игнорирования ошибок способен незаметно удалить символы; он не должен быть стандартным «исправлением» любого файла. Иногда нужно уточнить кодировку, отклонить документ или сохранить исходные байты для диагностики. Решение зависит от требований к сохранности информации.

При записи проверьте, требуется ли завершающий перевод строки и должны ли сохраняться внутренние пустые строки. Сравнение только визуально похожего вывода может пропустить различие. Для учебной задачи полезны входы без строк, с одной строкой, внутренней пустой строкой и строкой из пробелов. Каждый из них проверяет отдельное правило обработки.

Используйте временный файл, созданный тестом, с явно записанным содержимым и кодировкой. Тогда проверка не зависит от редактора, системной локали или старого файла в рабочем каталоге. Закрывайте файл до повторного чтения другим способом, если буферизация записи может влиять на наблюдаемый результат.
