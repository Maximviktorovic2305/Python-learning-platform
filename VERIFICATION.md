Проверялась новая программа: 4 раздела, 50 тем, 200 примеров, 100 курсовых программ, 1000 вопросов, 4 проекта. Отдельный тренажёр содержит 24 задачи: по 8 каждой сложности. Соответствие исходной программе и происхождение материалов описаны в [SOURCES.md](backend/app/content/SOURCES.md).

## Логика и содержание

- PostgreSQL: 275 backend-тестов прошли, включая конкурентное начисление XP и ротацию сессий.
- После добавления независимых случайных проверок: SQLite — 280 тестов прошли, 3 проверки конкуренции PostgreSQL пропущены. В это число входят 8 тестов сложных задач тренажёра на 96 входах с независимыми эталонными вычислениями.
- Запущены все 200 примеров, все входы 100 курсовых решений и 24 решений тренажёра. Заготовки не проходят полный набор проверок. Проверены уникальность вариантов ответов и распределение вопросов 4/4/2.
- Полный проход курса через API: 50 тем, 100 решений, все 1000 вопросов банка, 365 попыток теста, границы 60/70/100%, 515 проверок отсутствия повторных XP. Итог: 100% и 6500 XP. Проверены отказ для неверного решения и отсутствие ответов/решений в публичных контрактах.
- Полный проход через браузер: все 50 уроков по пяти этапам, 100 решений и 500 правильных ответов. Итог: 100%, 6500 XP, без ошибок страницы.
- Все 24 задачи тренажёра отдельно пройдены через интерфейс с локальным запуском и проверкой решения; 24 повторные отправки не дали XP. Итог: 720 XP, 24 решённые задачи, прогресс курса 0%, без ошибок страницы.

## Интерфейс и сборка

- Основной браузерный прогон новой программы до добавления тренажёра: 207 сценариев прошли в Chromium, Firefox и WebKit.

- На production-сборке проверен 51 сценарий: 50 прошли сразу; проверка адаптивной программы WebKit первоначально зафиксировала отменённые фоновые prefetch-запросы при принудительной смене документа. Сценарий переведён на переходы по ссылкам интерфейса с сохранённым контролем ошибок; повторная проверка во всех трёх браузерах прошла (3/3).

- В браузерах реально выполнялись многострочный input(), SQLite, SQLAlchemy, pytest и asyncio. Все 24 решения тренажёра запущены также в Pyodide.
- Успешны production build, TypeScript, ESLint, FSD (95 файлов), Prettier, Ruff, strict mypy API и runner, генерация OpenAPI/TypeScript и проверка Docker Compose. Runtime npm audit: 0 уязвимостей.

## База и границы проверки

Локальная настроенная база PostgreSQL предварительно сохранена в закрытую резервную копию вне Git. Удалены 240 из 241 пользователей, сохранена указанная владельцем существующая учётная запись с прежним ID, паролем, ролью и настройками. Учебная история, XP и сессии очищены. Итоговая проверка: 1 пользователь, 50 тем, 1000 вопросов, 100 курсовых и 24 самостоятельные задачи, 0 завершений, 0 сессий. Все проверочные аккаунты создавались в отдельных тестовых базах. Очистка удалённой production-базы не выполнялась.

Docker daemon локально недоступен. Автоматическая проверка разрешений отклонила запуск Docker Desktop с причиной `blocked by policy`; обход не предпринимался. Поэтому 10 Docker-тестов изоляции локально пропущены. Для локального полного прохода API/UI использовался отдельный непубликуемый QA-адаптер: он принимает только точное совпадение с авторскими решениями из репозитория и выполняет их в CPython. Произвольный пользовательский код в нём не исполняется. Это проверяет условия, входы/выходы, маршруты, оценки и XP, но не подтверждает контейнерную изоляцию.

В GitHub Actions настроены настоящие Docker-тесты и браузерный прогон с серверным исполнителем; их результат нужно смотреть для отправленного коммита. Развёртывание ожидает готовности runner после сборки образа и проверяет наличие SQLAlchemy/pytest в песочнице без сети. Проверка на физических iOS/Android-устройствах и ручное тестирование со скринридером не проводились.
