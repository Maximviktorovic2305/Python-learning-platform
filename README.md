# Python Lab

Образовательная платформа: от первой программы на Python до профессиональной разработки. Next.js App Router, React, строгий TypeScript, FastAPI, SQLAlchemy, PostgreSQL и отдельный исполнитель Python.

## Что работает

- Регистрация, вход, восстановление сессии, выход, профиль и смена пароля.
- Программа из **4 разделов и 50 опубликованных тем** по структуре основного курса Python Academy. Теория изложена своими словами; прежние материалы и неопубликованный каталог заменены.
- В каждой теме: теория, четыре разобранных примера, две программы для самостоятельной практики с исходными данными в заготовке, тест из десяти вопросов и закрепление. Всего 200 примеров, 100 практических заданий и 1000 вопросов. В тесте 4 easy, 4 medium, 2 hard; после отправки доступен разбор.
- Исходные данные практики записаны в начале solution.py. Поле для input() появляется только при необходимости. SQLAlchemy и pytest подготовлены в браузерном runtime и серверном образе. Потоки и процессы требуют серверного исполнителя.
- Отдельный раздел «Задачи»: 24 самостоятельные программы — по 8 лёгких, средних и сложных. Поиск, фильтры сложности и статуса, данные в заготовке, ожидаемый вывод, подсказки, редактор и запуск на странице. Черновики сохраняются отдельно для каждой задачи и пользователя на устройстве; серверная проверка выдаёт XP один раз и не изменяет прогресс курса.
- Происхождение программы и соответствие тем: [SOURCES.md](backend/app/content/SOURCES.md).
- Python в браузере с подсветкой, номерами строк, остановкой, ограничением времени и вывода. Runtime поставляется вместе с приложением.
- Независимая серверная проверка в одноразовых контейнерах. Браузерный результат не используется для выдачи XP.
- XP, серия занятий с часовым поясом, дневная цель, история активности, прогресс темы/модуля/уровня/курса, слабые темы и 16 достижений.
- Четыре проекта с заданиями и критериями. Отправка ссылки на работу; 500 XP только после одобрения администратором через API.
- Лендинг с зелёным питоном в области шапки, hero и статистики и вращающимся кубом Python над терминалом. Питон проходит поверх фона карточек, под текстом и кнопками. Адаптивная навигация, тёмная и светлая темы, клавиатурное управление и reduced motion. Обе анимации можно приостановить.

Все темы новой программы опубликованы. Порядок production-развёртывания описан в [deploy/README.md](deploy/README.md).

## Быстрый запуск в Docker

Нужны Docker с Linux containers и Compose v2, Python для генерации локальной конфигурации. Запускать из корня репозитория:

```sh
python scripts/configure_dev.py
docker compose --profile sandbox up --build -d
```

Откройте **http://localhost:3010**. Используйте именно `localhost`: Origin проверяется при операциях с сессией. При занятом порте поменяйте в `.env` одновременно `FRONTEND_PORT` и `ALLOWED_ORIGIN`, затем пересоберите frontend. Его `WEB_ORIGIN` и адрес API фиксируются при сборке.

Скрипт генерирует три независимых секрета и сохраняет существующий `.env`. Миграции и seed выполняются отдельным сервисом до запуска API. PostgreSQL и runner не публикуют порты на хост. Первый запуск загружает образы и Python runtime; runner дополнительно собирает образ песочницы с учебными библиотеками.

```sh
docker compose ps
docker compose logs --tail 50 backend runner
docker compose --profile sandbox down
```

`down` сохраняет данные. Не добавляйте `-v`, если хотите сохранить аккаунты и прогресс.

Для запуска без серверного исполнителя установите `EXECUTION_RUNNER=disabled` в `.env` и выполните `docker compose up --build -d`. Локальный Python и тесты продолжают работать; серверная проверка задач возвращает понятную ошибку 503 и не выдаёт XP. Пустой `RUNNER_TOKEN` в этом режиме допустим.

## Разработка без контейнеров приложения

Требуются Python 3.14+, Node.js 24+, npm и PostgreSQL 18. Создайте базу `python_lab` и задайте строку подключения в `backend/.env`, используя [backend/.env.example](backend/.env.example). `JWT_SECRET` должен содержать минимум 32 символа; секреты создавайте через `secrets.token_hex(40)` и сохраняйте локально. Frontend использует [frontend/.env.example](frontend/.env.example).

```sh
python -m venv .venv
# PowerShell: .venv\Scripts\Activate.ps1
# bash: source .venv/bin/activate
python -m pip install -r backend/requirements-dev.lock -e backend
cd backend
alembic upgrade head
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8010 --reload
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev -- --port 3010 --hostname 127.0.0.1
```

Для серверной проверки при нативном запуске нужен Docker. Сначала `docker build -t python-lab-sandbox:2026-10 runner/sandbox` из корня репозитория. В `backend/.env` задайте `EXECUTION_RUNNER=remote`, `RUNNER_URL=http://127.0.0.1:8090`, случайный `RUNNER_TOKEN` длиной не менее 32 символов. Передайте **тот же** токен в окружение процесса runner, затем из каталога `runner` запустите `uvicorn main:app --host 127.0.0.1 --port 8090`. API и runner перезапускаются после изменения окружения.

Swagger доступен на http://127.0.0.1:8010/docs только вне production. Проверка готовности: `/api/health`, включая обращение к БД. Привилегированные операции требуют роли `admin`; seed не создаёт администратора или аккаунт с известным паролем.

## Аналитика

Яндекс Метрика подключается переменной `NEXT_PUBLIC_YANDEX_METRIKA_ID`. Для этого проекта значение — `113659993`; пустое значение полностью отключает счётчик. В Docker Compose переменная читается из корневого `.env`, при нативном запуске — из `frontend/.env.local`. Это публичный номер счётчика, он попадает в сборку браузера. После изменения требуется пересобрать frontend.

SDK загружается только после отдельного выбора аналитики в уведомлении cookie. Переходы App Router учитываются как просмотры без дублирования; query/hash исключены из передаваемых URL. Код, ввод/вывод редактора и формы аккаунта скрыты от Вебвизора. Отозвать согласие можно кнопкой на странице cookie. Блокировка счётчика браузером не мешает сайту. Безусловный `noscript`-пиксель не используется, поскольку он отправлял бы запрос без выбора пользователя.

## Проверки

Архитектурные правила проверяются в [backend/tests/test_architecture.py](backend/tests/test_architecture.py): направления зависимостей, циклы, API-контракт и жизненный цикл ресурсов. PostgreSQL-тесты проверяют транзакции и конкурентные записи.

```sh
# Из корня, с активированным окружением Python
ruff check backend runner
ruff format --check backend runner
cd backend
mypy
mypy --strict ../runner/main.py
pytest -q
alembic check
```

Без `TEST_DATABASE_URL` API-тесты используют SQLite в памяти. Для проверки транзакций и конкуренции создайте отдельную PostgreSQL-базу **python_lab_test** и передайте `TEST_DATABASE_URL` в окружение. Fixtures удаляют и пересоздают таблицы только в тестовой базе; использование рабочего имени базы отклоняется. Сценарий конкурентного начисления XP требует PostgreSQL.

```sh
# Из корня; RUN_DOCKER_TESTS=1 в окружении, Docker запущен
pytest runner/test_sandbox.py -q

cd frontend
npm run typecheck
npm run lint
npm run lint:fsd
npm run format:check
npm audit --omit=dev --audit-level=low
npm run build
```

Сохранённые E2E-сценарии сейчас отключены и не входят в команды проверки. Для изменения этого режима требуется отдельное решение владельца.

В [GitHub Actions](https://github.com/Maximviktorovic2305/Python-learning-platform/actions) доступны результаты проверки каждого релиза. Тесты охватывают 50 тем, 200 примеров, 100 курсовых решений, 1000 вопросов и 24 задачи тренажёра. CI проверяет PostgreSQL, Docker-изоляцию, типы, линтеры, production-сборку и HTTP-ответы приложения. Браузерные сценарии и Axe отключены по текущему решению владельца; локальные браузерные проверки также не выполняются.

Сохранённые браузерные сценарии включают ошибки валидации, повторы после сетевых ошибок/429/503, изменение профиля и пароля, отправку и административное одобрение проектов, истечение/ротацию/replay токенов, выход между вкладками и отзыв всех сессий после смены пароля. Удаление аккаунта или работы пользователем пока не реализовано: DELETE возвращает 405 и сохраняет данные. Отдельно проверено, что удалённый при обслуживании БД пользователь больше не может войти по прежним токенам.

В dev-дереве npm audit обнаруживает пять high findings через ESLint → micromatch → braces; проверка runtime-зависимостей не обнаруживает уязвимостей. Автоматическое `npm audit fix --force` предлагает несовместимые изменения и не применяется. Контролировать обновления инструментов и повторять полный аудит перед релизом.

GitHub Actions повторяет типизацию, lint, проверку OpenAPI, PostgreSQL-тесты, Docker-изоляцию, сборку и браузерные сценарии на каждом push/PR. Все используемые Actions закреплены на commit SHA.

## API-контракт

Pydantic-схемы — источник контракта. После изменения схем:

```sh
cd backend
python -m app.export_openapi
cd ../frontend
npm run api:generate
npx prettier --write src/shared/api/schema.ts
```

Не редактируйте `schema.ts` вручную. `requirements.lock` содержит только runtime-замыкание зависимостей; `requirements-dev.lock` добавляет инструменты разработки. Обновлять lock-файлы нужно в отдельном окружении после установки согласованных версий: `python backend/scripts/lock_dependencies.py`. Скрипт фиксирует установленные версии, проверяет ограничения и не является независимым resolver.

Архитектурные ограничения закреплены в [backend/tests/test_architecture.py](backend/tests/test_architecture.py); порядок публичного развёртывания — в [deploy/README.md](deploy/README.md).

## Обновление программы и очистка базы

Обычный `python -m app.seed` заменяет старый каталог новым. Перед обслуживанием сохраните резервную копию базы.

Полная очистка с сохранением одной существующей учётной записи:

```sh
cd backend
python -m app.reset_learning --keep-email owner@example.com
python -m app.reset_learning --keep-email owner@example.com --apply
```

Первая команда только проверяет наличие аккаунта. Вторая удаляет остальных пользователей, сессии и учебный прогресс, обнуляет XP/серии сохраняемого аккаунта и заполняет новую программу в одной транзакции. Пароль, email, роль и настройки сохраняемого аккаунта остаются прежними. После сброса потребуется войти снова.
